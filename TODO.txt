ЭТАП 3: AUTH SERVICE
================================================================================

3.1. Инициализация проекта
    - Создать auth-service/go.mod
    - Установить зависимости:
      * github.com/go-chi/chi/v5
      * github.com/go-chi/cors
      * github.com/golang-jwt/jwt/v5
      * github.com/lib/pq (PostgreSQL driver)
      * github.com/jmoiron/sqlx - УБРАТЬ ДЛЯ MVP (использовать стандартный database/sql)
      * golang.org/x/crypto/bcrypt (хеширование паролей)
      * github.com/joho/godotenv (загрузка .env)
    - Создать main.go

3.2. Структура проекта
    - Создать структуру:
      * cmd/auth/main.go
      * internal/config/config.go
      * internal/database/database.go (подключение к БД)
      * internal/models/user.go (модель пользователя)
      * internal/repository/user_repository.go (работа с БД)
      * internal/service/auth_service.go (бизнес-логика)
      * internal/handler/auth_handler.go (HTTP обработчики)
      * internal/middleware/cors.go
      * internal/middleware/logging.go
      * internal/router/router.go
      * pkg/jwt/jwt.go (работа с JWT токенами)
      * migrations/ (SQL миграции)

3.3. Конфигурация
    - Создать config.go:
      * Порт сервиса (8081)
      * Параметры подключения к PostgreSQL
      * JWT секретный ключ
      * Время жизни токена
      * CORS настройки

3.4. Модель данных User
    - Структура User:
      * ID (UUID или int)
      * Email (string, unique)
      * PasswordHash (string)
      * FirstName (string)
      * LastName (string)
      * CreatedAt (time.Time)
      * UpdatedAt (time.Time)

3.5. Миграции БД
    - Создать migrations/001_create_users_table.sql:
      * Таблица users с полями из модели
      * Индекс на email
      * Ограничения (NOT NULL, UNIQUE)
    - Создать простой SQL скрипт для применения миграций
    - ПРИМЕЧАНИЕ: Для MVP не нужны сложные инструменты миграций

3.6. Database слой
    - Создать database.go:
      * Функция подключения к PostgreSQL
      * Функция закрытия соединения
      * Проверка соединения (ping)
    - Использовать connection pooling

3.7. Repository слой
    - Создать user_repository.go:
      * CreateUser(user) - создание пользователя
      * GetUserByEmail(email) - получение по email
      * GetUserByID(id) - получение по ID
      * ПРИМЕЧАНИЕ: UpdateUser и DeleteUser - УБРАТЬ ДЛЯ MVP (не нужны для базовой функциональности)
    - Использовать prepared statements
    - Обработка ошибок БД

3.8. JWT утилиты
    - Создать jwt.go:
      * GenerateToken(userID, email) - генерация JWT токена
      * ValidateToken(tokenString) - валидация токена
      * ExtractClaims(tokenString) - извлечение claims
    - Использовать HS256 алгоритм
      * Claims: user_id, email, exp, iat

3.9. Service слой (бизнес-логика)
    - Создать auth_service.go:
      * Register(email, password, firstName, lastName) - регистрация:
        - Проверка существования пользователя
        - Хеширование пароля (bcrypt)
        - Создание пользователя в БД
        - Возврат созданного пользователя (без пароля)
      * Login(email, password) - авторизация:
        - Поиск пользователя по email
        - Проверка пароля (bcrypt.CompareHashAndPassword)
        - Генерация JWT токена
        - Возврат токена и информации о пользователе
      * ValidateToken(tokenString) - валидация токена
      * GetUserByID(id) - получение пользователя

3.10. Handler слой (HTTP обработчики)
    - Создать auth_handler.go:
      * RegisterHandler(w, r) - POST /api/v1/auth/register:
        - Парсинг JSON тела запроса
        - Валидация данных (email формат, длина пароля)
        - Вызов Register из service
        - Возврат JSON ответа (201 Created)
        - Обработка ошибок (400, 409 Conflict если email занят)
      * LoginHandler(w, r) - POST /api/v1/auth/login:
        - Парсинг JSON тела запроса
        - Вызов Login из service
        - Возврат JSON с токеном и пользователем (200 OK)
        - Обработка ошибок (401 Unauthorized)
      * GetUserHandler(w, r) - GET /api/v1/auth/me:
        - Извлечение user_id из контекста (после JWT middleware)
        - Вызов GetUserByID из service
        - Возврат JSON с пользователем (200 OK)
        - Обработка ошибок (404, 500)

3.11. Middleware
    - CORS middleware (аналогично Gateway)
    - Logging middleware (логирование запросов)

3.12. Роутинг
    - Настроить Chi router:
      * POST /api/v1/auth/register - публичный
      * POST /api/v1/auth/login - публичный
      * GET /api/v1/auth/me - защищенный (JWT middleware)
      * GET /health - health check

3.13. Обработка ошибок
    - Единый формат ошибок
    - HTTP статус коды:
      * 400 - Bad Request (валидация)
      * 401 - Unauthorized (неверные credentials)
      * 404 - Not Found
      * 409 - Conflict (email уже существует)
      * 500 - Internal Server Error

3.14. Dockerfile для Auth Service
    - Мультистейдж build
    - Alpine образ
    - Порт 8081
    - Health check

3.15. Тестирование - УБРАТЬ ДЛЯ MVP
    - Для MVP достаточно ручного тестирования через Postman/браузер

    - Создать структуру:

      * internal/config/config.go
      * internal/database/database.go
      * internal/models/medical_record.go (модель медицинской записи)

      * internal/repository/health_repository.go

      * internal/service/health_service.go

    - Создать config.go:
      * Порт сервиса (8082)
      * Параметры подключения к PostgreSQL
      * CORS настройки

4.4. Модели данных
    - MedicalRecord:
      * ID (UUID или int)
      * UserID (int, foreign key)
      * Title (string)
      * Description (string, text)
      * RecordDate (time.Time)
      * DoctorName (string, опционально)
      * Diagnosis (string, опционально)
      * CreatedAt (time.Time)
      * UpdatedAt (time.Time)
    - HealthMetric (УПРОЩЕННАЯ ВЕРСИЯ ДЛЯ MVP):
      * ID (UUID или int)
      * UserID (int, foreign key)
      * MetricType (string: "blood_pressure", "pulse", "weight", "temperature")
      * Value (float64 - простое число, без сложных структур)
      * Unit (string: "mmHg", "bpm", "kg", "°C")
      * RecordedAt (time.Time)
      * Notes (string, опционально)
      * CreatedAt (time.Time)
      * ПРИМЕЧАНИЕ: Для MVP можно упростить - убрать сложные типы метрик, сделать только простые числовые значения

4.5. Миграции БД
    - Создать migrations/001_create_medical_records_table.sql:
      * Таблица medical_records
      * Foreign key на users (user_id)
      * Индексы на user_id, record_date
    - Создать migrations/002_create_health_metrics_table.sql:
      * Таблица health_metrics
      * Foreign key на users (user_id)
      * Индексы на user_id, metric_type, recorded_at
      * Composite index на (user_id, metric_type, recorded_at) для быстрого поиска

4.6. Database слой
    - Создать database.go (аналогично Auth Service)
    - Подключение к PostgreSQL
    - Connection pooling

4.7. Repository слой
    - medical_repository.go:
      * CreateRecord(record) - создание записи
      * GetRecordByID(id, userID) - получение записи (с проверкой владельца)
      * GetRecordsByUserID(userID, limit, offset) - список записей пользователя (простая пагинация)
      * UpdateRecord(record) - обновление записи
      * DeleteRecord(id, userID) - удаление записи
      * ПРИМЕЧАНИЕ: GetRecordsByDateRange - УБРАТЬ ДЛЯ MVP (достаточно базового списка)
    - health_repository.go (УПРОЩЕННО ДЛЯ MVP):
      * CreateMetric(metric) - создание показателя
      * GetMetricByID(id, userID) - получение показателя
      * GetMetricsByUserID(userID, limit, offset) - список показателей (без фильтрации по типу для MVP)
      * UpdateMetric(metric) - обновление
      * DeleteMetric(id, userID) - удаление
      * ПРИМЕЧАНИЕ: Для MVP убрать сложные фильтры (по дате, по типу) - оставить только базовый список

4.8. Service слой (бизнес-логика)
    - medical_service.go:
      * CreateRecord(userID, record) - создание записи
      * GetRecord(userID, recordID) - получение записи
      * GetUserRecords(userID, limit, offset) - простой список записей с пагинацией
      * UpdateRecord(userID, recordID, record) - обновление (с проверкой владельца)
      * DeleteRecord(userID, recordID) - удаление (с проверкой владельца)
      * Валидация данных перед сохранением
    - health_service.go (УПРОЩЕННО ДЛЯ MVP):
      * CreateMetric(userID, metric) - создание показателя
      * GetMetric(userID, metricID) - получение
      * GetUserMetrics(userID, limit, offset) - простой список без фильтрации
      * UpdateMetric(userID, metricID, metric) - обновление
      * DeleteMetric(userID, metricID) - удаление

      * ПРИМЕЧАНИЕ: Убрать сложные фильтры и историю для MVP

4.9. Handler слой (HTTP обработчики)
    - medical_handler.go:
      * CreateRecordHandler - POST /api/v1/medical/records:
        - Извлечение user_id из контекста
        - Парсинг JSON тела
        - Валидация
        - Вызов CreateRecord из service
        - Возврат 201 Created
      * GetRecordHandler - GET /api/v1/medical/records/:id:

      * DeleteRecordHandler - DELETE /api/v1/medical/records/:id:
